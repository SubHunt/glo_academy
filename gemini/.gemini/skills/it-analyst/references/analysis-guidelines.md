# Рекомендации по IT-анализу

## Выявление требований
- **Активное слушание:** Понимайте истинное "почему" за запросами пользователей.
- **Интервью со стейкхолдерами:** Проводите структурированные интервью для сбора различных точек зрения.
- **Фасилитация воркшопов:** Используйте совместные сессии для определения требований.

## Техники анализа
- **Метод MoSCoW:** Приоритезация требований (Must have, Should have, Could have, Won't have).
- **GAP-анализ:** Сравнение состояния "Как есть" (As-Is) и "Как будет" (To-Be).
- **SWOT-анализ:** Сильные и слабые стороны, возможности и угрозы.

## Лучшие практики документирования
- **Ясность и краткость:** Избегайте двусмысленности.
- **Прослеживаемость (Traceability):** Убедитесь, что каждое требование можно связать с бизнес-потребностью.
- **Валидация:** Проверяйте документы со стейкхолдерами на точность.

## Диаграммы
- **Используйте Mermaid для диаграмм:**
  - `graph TD` для блок-схем.
  - `sequenceDiagram` для взаимодействий.
  - `classDiagram` для структур данных.
