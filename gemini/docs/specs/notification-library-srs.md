# Спецификация требований к ПО (SRS): JS Notification Library

## 1. Введение
- **Назначение:** Описание требований к универсальной JavaScript-библиотеке для отображения уведомлений на веб-страницах.
- **Целевая аудитория:** Фронтенд-разработчики, системные архитекторы.
- **Область применения:** Любые веб-интерфейсы, требующие оперативного информирования пользователя.

## 2. Общее описание
- **Перспективы продукта:** Библиотека должна быть легковесной, независимой от фреймворков (Vanilla JS) и легко интегрируемой.
- **Функции продукта:**
    - Вывод уведомлений 4 типов: `success`, `attention`, `warning`, `info`.
    - Выбор позиции в одном из 4 углов экрана.
    - Автоматическое или ручное закрытие (требует уточнения, по умолчанию предлагается авто-закрытие).
- **Классы и характеристики пользователей:** Разработчики ПО, использующие библиотеку для встраивания в свои проекты.
- **Операционная среда:** Современные веб-браузеры (Chrome, Firefox, Safari, Edge).

## 3. Требования к внешним интерфейсам
- **Пользовательские интерфейсы:** Визуальные блоки уведомлений, накладываемые поверх контента страницы (z-index).
- **Программные интерфейсы:**
    - Подключение через `<script src="...">` (глобальный объект).
    - Поддержка `CommonJS` для сборщиков (Webpack, Rollup).
    - Поддержка `ES Modules` (`import/export`).
- **Интерфейсы связи:** Не требуются (работа на стороне клиента).

## 4. Системные функции
- **Функция 1: Инициализация и глобальная настройка.** Возможность задать дефолтный таймер (по умолчанию 5000мс) и позицию.
- **Функция 2: Создание уведомления (Метод `create`).**
    - Принимает объект с параметрами:
        - `title`: Заголовок уведомления.
        - `message`: Текст сообщения.
        - `type`: Одно из `success`, `attention`, `warning`, `info`.
        - `position`: Угол экрана (`top-left`, `top-right`, `bottom-left`, `bottom-right`).
        - `duration`: Индивидуальное время жизни (опционально).
        - `sticky`: Булево значение (если `true`, уведомление не закрывается автоматически).
- **Функция 3: Управление жизненным циклом.** 
    - Автоматическое удаление через 5000мс (или заданное время).
    - Остановка таймера для `sticky: true`.

## 5. Прочие нефункциональные требования
- **Бизнес-правила (Логика стекирования):**
    - Уведомления в одном углу выстраиваются в вертикальный стек.
    - **Нижние углы:** Новые уведомления появляются снизу, сдвигая старые ВВЕРХ (отступ от края экрана сохраняется для самого свежего).
    - **Верхние углы:** Новые уведомления появляются сверху, сдвигая старые ВНИЗ.
    - Уведомления не должны перекрывать друг друга.

## 6. Прочие требования
- **Дизайн:** Использование CSS-переменных для легкой кастомизации темы.
